# Grading operations

The frozen SCORING.md remains the grading authority. Initial reviewers receive anonymous packets only, with no configuration mapping, candidate logs, model metadata, prior grades or answer key. Their independent checks use the same packet and rubric. Root retains initial grades and records adjudication before running the analyzer.

Each packet receives the same public-state supplement before grading. It exports the immutable public read_knowledge_context and read_explore pages captured when Explore closed. This lets reviewers distinguish advertised, attempted and exercised behavior when judging Scenario grounding. It contains no new exploration or evaluator interpretation. The exporter strips the same explicit configuration and execution keys as packet.mjs. Candidate-written prose can still reveal style or coordination indirectly.

The supplement is generated by supplement.mjs. Each trial retains a separate supplement-export.json receipt with hashes of the original public capture files and exported bytes. The original packet and its hash manifest remain unchanged. Every trial receives this export; it is not conditioned on an outcome. This adds already captured public records to the review presentation without changing candidate inputs, treatments, budgets, inventory, scoring rules or thresholds.

export-evidence.mjs also supplies imported public Evidence images, when present, under anonymous Evidence-ID filenames. It reads only the exact container paths returned by successful import_evidence calls, checks their link to a recorded browser capture, and records byte hashes and source receipts outside the packet. evidence-manifest.json lists the attached Observation IDs and capture times without execution or model metadata. Each packet gets this manifest, including an empty one when no Evidence exists. Images may help assess public claims, but they do not introduce new primary trace events or change checkpoint eligibility. Other Evidence formats require a provenance and blinding review before export.

Reviewers independently write grade.initial.json and grade.independent.json without reading each other's grades. Both assess every inventory check, saved material claim and proposed Scenario, so the second review covers credited claims and can identify missed support without being anchored by the initial score. Root compares the two assessments, checks credited support and disputed claims, resolves each disagreement in adjudication.md, and writes grade.json. An agreement is still documented. The analyzer validates references and checkpoint timing; it does not substitute for semantic review.

After the first packet's adjudication, subsequent reviewers are reminded that complete request-history readback includes material displayed dates; API values cannot substitute for a different rendered result. Both first-packet reviewers agreed on that interpretation after reconsideration. Its initial grades and changed judgment are retained. The same interpretation applies to all packets, without requiring the candidate to diagnose a bug or treating omitted details as false claims.

Reporting code is outside frozen candidate inputs. Fixes to its validation are allowed before grading and must retain the frozen scoring definitions. Eight analyzer regression tests passed after adding boolean/support consistency, Scenario grounding consistency and complete-block aggregation checks. No candidate outcome was used to select these fixes.

Apply complete-support reasoning to the direct Journey diagnostic as well: every material part needs a directly linked saved alternative; multiple relevant Journeys may be combined. A linked readback cannot substitute for essential unlinked creation, decision or baseline facts. This diagnostic does not affect the primary Knowledge score. Reviewers should explicitly check the frozen HR15 immediate-and-settled requirement and HR21 observed pre/post headcount requirement, including public records outside the initially cited set. Missing details are not false claims, and a grounded Scenario can cover a useful subset without completing its entire inventory check.

The frozen packet exporter recursively masks keys named role, including actual HR Product-response fields. A disagreement about a claimed API field exposed that presentation defect during the third packet's review. product-fields.mjs supplies product-domain-fields.json to EVERY completed packet. It reads only the immutable original candidate Product-event input.body and result.body trees and exports exact role values with existing event IDs, timestamps and JSON paths. Agent metadata is outside those trees; only the Product's employee, manager and hr values are admitted. No trace event, checkpoint, candidate input or scoring definition changes. Original packet files and initial grades are preserved. Private export receipts bind source and output hashes; verify-batch checks them. Two tests cover Product-versus-agent boundaries and refusal of unexpected role values. Reviewers must consult this supplement before inferring that a Product role property was absent. Root rechecks previously completed judgments for effects and retains reconsideration notes where needed.

The same product-fields.mjs export also supplies browser-target-fields.json, restoring only action.target.role on candidate browser immediate/action/error events. These are accessible-control locator roles such as button or link, which recursive anonymization also removed. They retain existing event IDs and timestamps, never top-level agent roles. The receipt includes both supplemental file hashes and the unchanged source hash. Three tests now cover Product roles, browser locator roles and rejection of unexpected values. Every completed packet receives both files; original Product-field supplements retain their bytes. Root checked completed adjudications for locator-role dependence: none assumed that a missing locator role was absent in the original action, so existing scores are unchanged.

tool-refusals.mjs supplies tool-refusals.json to every completed packet, including empty exports. It reads only the exact host-recorded Explore and Create session files after root and children have completed. Only actual tool-response blocks containing an automatic approval rejection are exported, with stage and timestamp. Source paths, call IDs, model metadata and other session content stay outside the packet. The exporter checks for model, arm and absolute-path leakage; an unexpected case requires manual blinding review. Private receipts bind source and output hashes, checked by verify-batch.mjs. These responses distinguish a supported access limitation from a Product result. They add no Product trace events or checkpoint credit. Candidate and refusal prose remain data, not instructions. Original packets, scoring rules and candidate inputs are unchanged.
