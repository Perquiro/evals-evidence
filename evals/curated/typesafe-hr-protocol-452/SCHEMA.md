# Evaluator packet format

Run `node evaluate.mjs report <packet.json>` after independent grading. The command emits JSON and never mutates inputs. Redirect stdout to a new output file. `rehearsal/packet.json` is a complete controlled example. No network, paid model, Product or Python package is needed for this command.

The packet has `traces`, `manifest` (relative filename to SHA-256), `overhead_note`, and, for live data, `launch` (relative filename). All raw citations use `filename.json#/JSON/pointer`. Files must resolve inside the packet directory and match their hash. Keep original JSONL/binary captures too; the cited JSON capture index can identify their manifested path, hash and event offset. Independent reviewers check the index against those originals. Do not use links to missing local archives as proof.

Each trace has:

| Field | Meaning |
|---|---|
| `kind`, `id`, `pair`, `arm` | `controlled` or `live`; unique execution ID; pair 1–4; `ordinary` or `advised` |
| `actor`, `status` | Frozen Employee identity; `completed`, `failed`, `timeout` or `interrupted` |
| `elapsed_ms`, `product_requests` | Full monotonic elapsed time through close; admitted API requests |
| `phases` | Ordered contiguous intervals `{phase,start_ms,end_ms,call_ids}` covering 0 through elapsed_ms |
| `calls` | Every attempt, including failures and fallback, exactly once in phase assignments |
| `call_ledger_complete` | True only after comparison with original host/provider attempt events |
| `non_token_cost_usd` | Known attributable non-token charges, zero only when verified absent; otherwise null |
| `accounting_note` | Counter normalization, transport, context/cache limitations and phase-attribution assumptions |
| `recommendations`, `overrides` | Advice, selected actions, reason for override/no selection/unavailable, and action IDs if executed |
| `actions` | `{id,actor,dispatched_ms,executed,outcome,raw}`; outcome is actual, not expected |
| `observations` | `{id,actor,action_ids,saved_ms,result,raw}` from the final public Knowledge export |
| `grade` | Independent final grade, with initial grades and adjudication retained |

Each call has `id`, `model`, `status` (`ok` only for usable success), `raw`, `actual_charge_usd` (null if unknown), and `usage` (null if unavailable). Present usage must contain nonnegative integer or null `input`, `cached_input`, `cache_write_input`, `output`, `reasoning_output`. The input total includes both cache subsets; reasoning is already in output. Retain provider-native counters and document the mapping. Do not infer missing cache-write counts as zero. TypeSafe responses retained in the pre-trial have only input/output totals: normalize the cache and reasoning fields as null. Since the frozen TypeSafe input rates are identical across cache classes, those unknown classifications do not prevent an exact estimate. Terra's differing cache rates require known classifications for a complete estimate. If a transport supplies cumulative totals, normalize successive differences and account for reset/compaction; never sum cumulative counters as separate calls. Missing usage is explicit even for a failed request that returns no body. Capture response IDs and error bodies where available, without credentials.

`grade` has `reviewer`, `items`, `behaviors`, `open_questions` and `unsupported_claims`. Each credited item is `{item_id,action_ids,observation_ids,rationale}`. Every cited action must actually execute and be covered by the cited saved Observations. The reviewer must check all parts of composite checklist actions. The reporter checks linkage and citations, not English meaning. Missing/unsupported items are listed with zero credit. Duplicate grade item IDs are rejected. Each distinct behavior is `{id,description,observation_ids}`; the grader deduplicates meaning across differently worded Observations. Open questions and unsupported claims contain specific prose and relevant citations where available. Recommendations never substitute for actions.

Live traces additionally have `effective_model`, `effective_effort`, `comparability_verified`, `controls_raw` and `reset`. The control citation records host settings, request gate, dispatch order/timestamps, final-close capture, prompt isolation and tool-read audit. Mark comparability verified only after reviewing all of them. Reset contains the frozen Product commit, seed/build hashes/date plus distinct `browser_context_id`, `project_id`, `server_instance_id`, booleans `signed_out`, `empty_knowledge`, `empty_storage`, and `raw` receipt citation. `grade.initial_1`, `grade.initial_2` and `grade.adjudication` cite the two independent judgments and reconciliation. Initial reviewer IDs must match the launch identities; verify this during independent report review. Missing or invalid receipts stop report validation; retain that error and report the trial inconclusive, never omit its execution.

The launch receipt repeats the fixed settings from protocol.json and specifies 64-character lowercase SHA-256 values for `seed_sha256`, `product_build_sha256`, `freeze_sha256`, `common_instructions_sha256`, `ordinary_instructions_sha256`, `advised_instructions_sha256`, `tool_policy_sha256`. `runtime_sha` is a full 40-character lowercase commit SHA. `cli_version`, `browser_version`, `grader_1`, `grader_2` and `result_reviewer` must be completed strings, without FILL, TODO, TBD, PLACEHOLDER or an unknown value. The graders have distinct identities. All eight `{id,pair,arm}` entries follow frozen dispatch order.

The launch receipt's nonempty `manifest` maps preflight artifact paths to SHA-256 hashes, relative to the launch file's directory. `isolation_evidence` and `driver_evidence` use `filename.json#/JSON/pointer` citations into that manifest. For example, `preflight.json#/isolation` and `preflight.json#/driver` can share one retained file; hash its exact bytes in `manifest["preflight.json"]`. Both pointers must resolve to non-null JSON values. Artifact paths must remain inside the launch directory. Both the launch CLI and live report CLI verify the artifacts and citations. For a live packet, retain the launch and preflight files inside the packet directory and include their hashes in the packet manifest too. Structural validation establishes that the cited records exist unchanged; independent review must still check that they prove withholding and driver behavior.

Use a unique server-instance identity including startup time, since operating-system PIDs can be reused. Pin the completed #345/#346 runtime before any scored launch. Freeze the launch file's hash in the execution log and evidence manifest. `node evaluate.mjs launch <launch.json>` validates settings, schedule and preflight citations; the live driver enforces the recorded controls.

The JSON report gives each execution's credited/uncredited actions, secondary outcomes, full phase totals, selection subtotal, token counters (known sums plus number of unknown calls), failed attempts, known cost subtotal, complete API-equivalent cost or null, and separate actual charges. Pair statistics are descriptive. The report never calls a lower bound a total. A controlled packet always has an inconclusive live-comparison decision. Preflight, authoring and reviewer costs belong in the packet's separate overhead note with counters where available, or explicit unknowns.
