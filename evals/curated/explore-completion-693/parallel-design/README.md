# Parallel workflow design comparison

Three isolated architecture candidates addressed a scout, director and bounded page workers with one shared allowance. The anonymous packages and independent judge's exact output are retained. The judge chose Birch with 17/18, versus Maple 12 and Cedar 8. The parent read all six package files and chose Birch, with the specific grafts and rejected alternatives recorded in `synthesis.md`.

All three written packages were available. Composer completed normally; Sol and Grok timed out during their final checks. The runner's overall outcome was `ok`. These artifacts support design comparison, not a claim that every helper completed normally. Opus was unavailable due to the previously confirmed weekly quota, so the configured fallback was used.

The selected structure separates immutable Actor/Page leases and browser queues while retaining global request admission, a shared clock and a short Knowledge-operation queue. Read tasks can overlap across Actors; mutations require exclusive Product access. The matched treatment uses the same workflow and models with concurrency one or three.

The implementation, native overlap gate and scored comparison are still pending. A design vote does not establish higher saved coverage. The completed earlier pilot remains 3/27, 2/27 and 1/27, and no package replaces those results.
